# CLAUDE.md — GitLab CI/CD Dashboard (Self-Hosted)

## What is this?

Self-hosted GitLab CI/CD monitoring dashboard. Users deploy via Docker and connect their GitLab instance.
SaaS web platform (sister repo): `../gitlab-ci-dashboard-web`

## Tech Stack

- **Next.js 15** (App Router) + React 19 + TypeScript 5.9
- **Prisma ORM** + PostgreSQL 17 + Redis
- **Zustand** state management
- **Tailwind CSS 3** + Lucide icons
- **Jest** + React Testing Library
- **Docker** multi-stage build (Node 20 Alpine)

## Commands

```bash
npm run dev          # Dev server :3000
npm run build        # Production build
npm run lint         # ESLint
npm run test         # Jest tests
npm run db:generate  # Prisma client
npm run db:push      # Apply schema
npm run seed         # Create admin user
```

## Architecture

```
src/app/           → Pages + API routes (App Router)
src/components/    → React components (34 dirs)
src/hooks/         → Custom hooks (10 files)
src/lib/           → Business logic (gitlab/, auth/, license/, db/, org/)
src/store/         → Zustand stores
src/middleware.ts   → Auth + org detection middleware
prisma/            → Schema + migrations
```

### Key Files

- `src/lib/license.ts` — License validation (JWT RS256, online/offline dual)
- `src/lib/gitlab-api.ts` — Full GitLab API client
- `src/lib/dora-metrics.ts` — DORA metrics calculation
- `src/lib/auth/` — Session/JWT auth (SESSION or SUPABASE mode)
- `src/lib/csrf.ts` — CSRF protection
- `prisma/schema.prisma` — DB models (multi-tenant: Org → Members → Users)

### Auth Modes

- **SESSION** (default): Local admin user, bcrypt passwords, JWT sessions
- **SUPABASE** (cloud): Supabase auth, used when deployed as managed service

### License System

Dashboard validates licenses generated by the web platform:
- JWT RS256 signed tokens
- Online verification via `LICENSE_VERIFICATION_URL`
- Offline verification via embedded `LICENSE_PUBLIC_KEY`
- Plans: free (5 projects, 2 users), pro, team, enterprise

## Credentials

All secrets in `.env` (never committed). See `.env.example` for full template.

**Required:**
- `POSTGRES_PASSWORD`, `REDIS_PASSWORD` — DB/cache auth
- `ADMIN_PASSWORD` — Initial admin user
- `SESSION_SECRET` — JWT session signing (64+ chars)

**Optional:**
- `LICENSE_KEY` — JWT license from SaaS platform
- `LICENSE_ENCRYPTION_KEY` — AES-256-GCM for stored keys (`openssl rand -hex 32`)
- `LICENSE_PUBLIC_KEY` — RSA public key for offline verification
- `SUPABASE_*` — Only for cloud mode (AUTH_MODE=supabase)
- `CLOUD_WEBHOOK_SECRET` — Shared secret with web platform
- `TOKEN_ENCRYPTION_KEY` — Encrypts GitLab tokens in DB

- **Docker Compose**: `docker-compose.yml` (session) or `docker-compose.cloud.yml` (supabase)

## Session Protocol — MANDATORY

### Starting a Session

```bash
bd prime                       # Load workflow context
bd ready                       # Find unblocked work
bd list --status=in_progress   # Check active work
bd list --status=open          # All open issues
```

Always check bd history first. Understand what was done before, what's in progress, and what's blocked.

### During Work

- Track ALL work in bd issues
- `bd update <id> --status=in_progress` before starting
- `bd comments add <id> "progress note"` for updates
- Keep commits small and frequent

### Ending a Session

```bash
# 1. Quality gates (if code changed)
npm run lint && npm run build

# 2. Stage and commit code
git add <files>
git commit -m "descriptive message"

# 3. Close completed issues
bd close <id1> <id2> ...

# 4. File issues for remaining/discovered work
bd create --title="..." --type=task --priority=2

# 5. Sync and push — MANDATORY
bd sync
git push

# 6. Verify
git status   # Must show "up to date with origin"
```

**Work is NOT done until `git push` succeeds.**

## Code Standards

- TypeScript strict mode — no `any` unless unavoidable
- Components: PascalCase (`PipelineCard.tsx`)
- Hooks: `use` prefix (`useConfigLoader.ts`)
- API routes: kebab-case directories
- Tests: `.test.ts` suffix
- Always run `npm run lint` before committing
