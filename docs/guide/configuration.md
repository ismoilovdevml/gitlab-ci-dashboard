# Configuration

All server settings live in `.env`, next to `docker-compose.yml`. Compose reads it and passes the
values to the containers. After editing `.env`, apply the change with:

```bash
docker compose up -d
```

The GitLab URL and access token are **not** environment variables. They are set per user in the
dashboard under **Settings**; see [Connecting GitLab](./connecting-gitlab).

::: warning Keep `.env` private and backed up
It contains every password and key of the install (the installer creates it with mode `600`).
Losing `TOKEN_ENCRYPTION_KEY` makes stored GitLab tokens unreadable; changing
`GITLAB_WEBHOOK_SECRET` invalidates the secret token of every GitLab webhook.
:::

## Variables in `.env`

These are the variables in `.env.example` and in the file generated by the installer.

### Database and cache

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `POSTGRES_USER` | no | `gitlab_dashboard` | PostgreSQL user |
| `POSTGRES_PASSWORD` | **yes** | none | PostgreSQL password. Set before the first start: PostgreSQL stores it when the volume is created |
| `POSTGRES_DB` | no | `gitlab_dashboard` | PostgreSQL database name |
| `REDIS_PASSWORD` | **yes** | none | Redis password (`requirepass`) |

### App

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `NODE_ENV` | no | `production` | Node.js environment. Keep `production` |
| `DASHBOARD_PORT` | no | `3000` | Host port the dashboard is published on: `PORT` (all interfaces), `IPV4:PORT` or `[IPV6]:PORT`. Use `127.0.0.1:3000` behind a reverse proxy on the same host |

### Initial admin

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `ADMIN_USERNAME` | no | `admin` | Username of the admin created on first start |
| `ADMIN_PASSWORD` | **yes** | none | Password of that admin. At least 12 characters and not the `CHANGE_ME` placeholder. Only used when the admin does not exist yet |
| `ADMIN_EMAIL` | no | `admin@example.com` | Email of that admin |

Changing `ADMIN_PASSWORD` later does not change the password of an existing admin. Use
**Settings → Change Password** in the dashboard.

### Security

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `SESSION_SECRET` | **yes** | none | Signs CSRF tokens. Without it every state-changing request fails. Use a long random value: `openssl rand -hex 32` |
| `TOKEN_ENCRYPTION_KEY` | recommended | none | Encrypts GitLab tokens stored in PostgreSQL (AES-256-GCM, key derived with scrypt). If unset, tokens are stored in plain text. `openssl rand -hex 32` |
| `GITLAB_WEBHOOK_SECRET` | recommended | none | Secret token GitLab must send with webhooks (`X-Gitlab-Token`). Per-organization webhook secrets are derived from it. If unset, the install-wide webhook URL accepts unauthenticated requests and per-organization URLs return `503`. `openssl rand -hex 32` |

The installer and `scripts/generate-env.sh` generate all three.

## Variables for running outside Compose

`docker-compose.yml` builds the connection strings from the values above. Set these yourself only
when you run the app directly with `npm run start` or `npm run dev`:

| Variable | Default | Description |
|----------|---------|-------------|
| `DATABASE_URL` | none (required) | PostgreSQL connection string, for example `postgresql://gitlab_dashboard:PASSWORD@localhost:5432/gitlab_dashboard?schema=public` |
| `REDIS_URL` | none | Redis connection string, for example `redis://:PASSWORD@localhost:6379` |
| `REDIS_HOST`, `REDIS_PORT` | `localhost`, `6379` | Used with `REDIS_PASSWORD` when `REDIS_URL` is not set |
| `PORT` | `3000` | Port the Next.js server listens on |

## Deprecated

| Variable | Status |
|----------|--------|
| `LICENSE_ENCRYPTION_KEY` | Older installs encrypted GitLab tokens with it. It is still read when `TOKEN_ENCRYPTION_KEY` is unset, but the current `docker-compose.yml` does not pass it to the app. Copy its value to `TOKEN_ENCRYPTION_KEY`; see [Troubleshooting](./troubleshooting#gitlab-tokens-cannot-be-decrypted-after-an-upgrade) |

## Settings in the dashboard

Stored per user in PostgreSQL and changed under **Settings**:

- GitLab URL and access token
- theme (dark or light)
- auto-refresh on or off, and the interval (5 s to 5 min)
- in-dashboard notifications for failed and successful pipelines
- password

![Settings page](/screenshots/settings.webp){.screenshot}

Alert channels (Slack, Telegram, Discord) are configured under **Alerting**; see
[Alerting and webhooks](/features/alerting).
